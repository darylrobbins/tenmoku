# UI polish audit and visual directions (T1429)

The **should** beside `docs/design-language.md`'s **is**. That file records what
the code does today (T1273); this one audits it surface by surface for the first
public release (macOS only, editor-first, "beautiful: curated JetBrains-lite" as
a product pillar), proposes three visual directions and breaks the work into
cards. Rules and gaps already in `docs/design-language.md` are cited by section
(for example "design-language § Gaps › Type") and not repeated.

Pixel values are logical pixels. The captures are 2× (2000 × 1200 for a
1000 × 600 window), so a value measured on a capture is halved here.

## Status

**proposed.** The user (Daryl Robbins) approves. This card changes no product
visual and files no implementation card: the user picks a direction first, then
the lead readies the cards under [Proposed card breakdown](#proposed-card-breakdown).

## Captures

Every capture is regenerated by one command, on the Mac (Metal), with no golden
compared and no screen-recording permission needed:

```text
cargo run -p fe-workbench --example screenshots -- audit target/ui-audit
```

It runs in about 80 s once built and writes 41 PNGs. The code is
`crates/fe-workbench/examples/screenshots/audit_scenes.rs`. Each scene is the demo
project of the golden scene (`scenes.rs:write_project`) in a 1000 × 600 window
with the title bar on, then a few steps, each on its own frame: a command
dispatched as its key would, or a call into fe-workbench's public API. The run
re-executes itself with `TENMOKU_CONFIG_DIR`, `TENMOKU_STATE_DIR` and
`XDG_CACHE_HOME` on a fresh temporary folder, whatever they were set to, and the
child refuses to start unless they point there (`audit_scenes.rs:isolated`). So
no real settings or keymap show, and the demo folders it opens go into a
throwaway `recent.toml`, not the user's. (The golden run's own scenes don't do
this yet and record their demo folders in the real one: card P15.) Git scenes make the project a repository with two
commits (fixed author and dates), a modified `src/main.rs`, a staged
`src/util/split.rs` and an untracked `NOTES.md`. Dark is Tenmoku Dark with no
settings; light is Tenmoku Light with `[theme] mode = "light"`.

### Left out, and the test hook each needs

None of these is opened through fe-workbench's public API from the example
without a change under `src/`, which this card doesn't make. Card P15 adds the
hooks.

| Surface | Why it's left out | Hook it needs |
| --- | --- | --- |
| Terminal panel | `terminal.toggle` spawns a login shell (`crates/fe-workbench/src/terminal_panel.rs`); its prompt, colours and timing depend on the user's shell config, so the capture would be neither hermetic nor stable | A `#[doc(hidden)]` `TerminalPanel::open_with_session(…)` taking a fake session fed fixed bytes, or a `terminal.shell` override the example can set to `/bin/cat` |
| Peek (definition and references) | It opens only on a language server's answer (`crates/fe-workbench/src/peek.rs`); the example has no server, and fe-lsp's fake needs its `test-support` feature, trust and a launcher | A `#[doc(hidden)]` `Workbench::show_peek(locations, window, cx)` that opens the widget on given `(path, range)`s |
| Completion menu | `EditorView::set_completion_provider` is public, but `crates/fe-workbench/src/lsp.rs:Workbench::sync_lsp` puts the language servers' provider back on every editor after each draw, and `set_completion_provider` closes the menu | A `#[doc(hidden)]` `EditorView::show_completions(CompletionList, cx)`, or a workbench switch that leaves an editor's provider alone |
| Git log's commit card | It's a hoverable tooltip (`crates/fe-workbench/src/git_log.rs`, `hoverable_tooltip`), shown after GPUI's 500 ms tooltip delay, which the capture's settling doesn't wait for | A `#[doc(hidden)]` `GitLogPanel::show_card(ix, window, cx)`; the panel type is crate-private today, so also a `Workbench::git_log_panel()` accessor |
| Problems panel with rows | Only the empty state is captured: diagnostics come from language servers and task runs | A `#[doc(hidden)]` `Workbench::set_diagnostics_for_audit(path, diagnostics)`, or reuse the peek hook's fake LSP |

## Cross-cutting

### Spacing scale

Names for design-language § Spacing's de-facto scale, as constants in
`kiln/crates/kiln-ui/src/theme.rs` beside `ROW_HEIGHT` (no new module):

| Name | Value | For |
| --- | --- | --- |
| `space::XXS` | 2 | Icon to its badge; a chevron to its icon |
| `space::XS` | 4 | Inside a dense control; a tree row's box inset |
| `space::S` | 6 | Icon to label |
| `space::M` | 8 | Between controls; a popover's padding; a status entry's padding |
| `space::L` | 12 | A panel's side padding; a row's inset in settings |
| `space::XL` | 16 | Between groups; around floating content |
| `space::XXL` | 24 | Between sections; a page's margin |

Off-scale values go: settings' 10 → 12, Markdown's 26 → 24 and 20 → 16, the
literal indents 22 and 44 → `TREE_INDENT` multiples (design-language § Gaps ›
Spacing). Heights become roles too: `height::ROW` 24, `height::CONTROL` 24 (B) or
28 (A), `height::HEADER` 22, `height::TAB` 30 (B) or 32 (A), `height::HANDLE` 5
everywhere (split pane's 6 goes).

### Type ramp

Named roles replace the literals (design-language § Type, § Gaps › Type). One
root size, set once in `kiln/crates/kiln-shell/src/root.rs`; Tenmoku's override in
`Workbench::render` goes.

| Role | Dense (B, C) | Native (A) | Weight | Replaces |
| --- | --- | --- | --- | --- |
| `caption` | 10 | 10 | regular | the dense lists' 10 |
| `small` | 11 | 11 | regular | descriptions, git labels, section labels' 11 |
| `body` | 12 | 13 | regular | chrome's 12, kiln's 13 |
| `section` | 11 | 11 | semibold, `text.muted`, tracking +0.2 | panel and page section labels |
| `emphasis` | 12 | 13 | semibold | settings row titles, card author |
| `title` | 13 | 15 | semibold | prompt message 14, settings heading 15 |
| `display` | 20 | 22 | semibold | the Start page's title |

The editor keeps `editor.font_size` (13); editor popovers keep the editor's size
for code and use `body` for prose. Toasts drop `text_sm`/`text_xs` for `body`
and `small`.

### Radius and border rules

- **Inline controls** (buttons, inputs, crumbs, tree selection, toggles): 4.
- **Floating surfaces** (palette, pickers, menus, popovers, hover, toasts,
  prompts, the commit card): 8, `surface.raised`, 1 px `border.default`,
  `shadow_md`; modal ones (prompt, setup sheet) `shadow_lg`.
- **Panels and panes**: 0, separated by 1 px `border.default`. Inside a panel,
  `border.subtle`.
- The 3 px radius and `rounded(px(4.))` literals go (design-language § Gaps ›
  Spacing). The focus outline follows the element's radius.

### Focus ring and hover/pressed

- **Focus ring**: 2 px `state.focus_ring` outside the element (inset 0 for
  rows), only for keyboard focus where the platform distinguishes it; text
  inputs show `border.focused` instead. A list with focus shows its selected row
  with `list.row_focus_border`; without focus, `list.row_selected_inactive`.
- **Focused pane**: the active tab's 2 px accent bar (CH3); unfocused panes'
  active tabs have none.
- **Hover**: `state.hover` fill on anything clickable that isn't a text field,
  rows included; icon buttons get a 4-radius fill 2 px larger than the icon box.
- **Pressed**: `state.pressed` over the hover fill, no movement.
- **Disabled**: 50% opacity of the enabled look, not a separate grey fill
  (GP3), except filled primary buttons, which keep `state.disabled`.
- **Selected vs hovered**: never the same colour; selected wins.

### Motion policy

Today there's none (design-language § Motion). The policy adds a little, all of
it off when `App::reduce_motion` is set. Nothing sets that from macOS's Reduce
Motion yet; the accessibility design card filed beside this one (VoiceOver
feasibility) covers wiring it, and the screenshot harness sets it on so
captures stay single-frame.

| What | Motion | Duration | Easing |
| --- | --- | --- | --- |
| Palette, pickers, prompt, setup sheet open | fade 0→1 and scale 0.98→1 | 120 ms | ease-out (cubic) |
| Same, close | fade | 80 ms | ease-in |
| Popovers (hover, completion, commit card) | fade | 100 ms, after the existing delays | ease-out |
| Toasts in / out | slide 8 px up and fade / fade | 160 / 120 ms | ease-out / ease-in |
| Dock show/hide, panel resize by command | none: layout changes stay instant | — | — |
| Peek open | the reserved rows grow | 120 ms | ease-out |
| Theme change | none | — | — |
| Caret | no blink (editor-first, calm); a setting can turn blink on later | — | — |
| Scrolling | none beyond the platform's own | — | — |

Rules: no motion over 200 ms; nothing loops; nothing moves the text the user is
reading except peek; under Reduce Motion everything above is instant.

### Empty-state rules

An empty panel or page shows, centred in the top third: a 32 px Lucide icon in
`text.muted`, a `title`-role line saying what would be here, one `body` line in
`text.muted` saying how to get it, and at most one button. No empty state is a
single muted line in a corner (PB2), and none leaves a toolbar row with nothing
in it (SP4). The Start page is the app's empty state and follows the same
centring (SP1).

### WCAG contrast

Ratios of `text.primary`, `text.muted` and `text.disabled` on `surface.background`,
`surface.panel` and `surface.raised` for each bundled theme, the tokens resolved
as kiln resolves them (a theme's own value, else the base's, else its rule:
`raised` = background 8% towards primary, `muted` = primary 50% towards

## Visual directions

All three keep what's already right and isn't direction-specific: the editor
itself (font, 1.6 line height, syntax colours), Lucide for chrome, native
Open/Save panels and NSAlert sheets, the dock/rail layout, and the 24 cards the
breakdown marks "all" (P1–P27 less P13, P14 and P20), whose values follow the
direction where it matters (P9's type ramp).

### A. Native Mac ("Xcode / Nova / Tower")

macOS-first: the window looks like it shipped with the OS.

- **References:** Xcode 26, Panic's Nova, Tower, Apple Notes' sidebar.
- **Changes:** unified toolbar title bar 52 px with the lights at (20, 19), a
  document title with edited dot and a centred segmented "scheme" area;
  vibrancy (`WindowBackgroundAppearance::Blurred`) behind the dock and title bar,
  so `surface.panel` becomes translucent; the native type ramp (body 13, title
  15); rows 28, controls 28; radius 8 for floating, 6 for controls; SF Symbols
  look-alikes at 16 in the rail; find as a floating bar; the full HIG menu set;
  sheets for the setup wizard. Motion as the policy, plus Mac's sheet slide.
- **Stays:** editor, file icons, dock structure, keymaps.
- **Cost:** 28 cards: the 24 shared, then A1–A4 (vibrancy, the 52 px toolbar,
  a floating find bar, the density pass) in place of P13, P14 and P20.
- **Density risk:** high. Rows 24 → 28 and body 12 → 13 lose about 15% of the
  tree's visible rows, and the title bar takes 20 more.
  Vibrancy lowers chrome contrast by design.
- **Fit with "curated JetBrains-lite, beautiful":** beautiful, but not
  JetBrains-lite: it trades the information density JetBrains users come for.

### B. Curated New UI ("JetBrains New UI / Fleet, on a Mac")

JetBrains' 2023+ New UI, pared down: dense, flat, a strong icon set, colour
only where it carries meaning, with macOS-correct menus and dialogs.

- **References:** IntelliJ IDEA / RustRover New UI (compact mode), JetBrains
  Fleet, Xcode's menus and sheets for the native parts.
- **Changes:** title bar 38 px holding back/forward, a project widget and a
  branch widget on the left and the run/task widget on the right (CH6, TB1,
  TB2); one heading per tool window (CH2); tool windows can be bottom-docked
  (the Git log, GL2); body 12 / title 13 ramp with explicit roles; rows 24,
  controls 24; radius 4 inline and 8 floating; accent bar on the active tab;
  icon buttons with filled on-states for every toggle (find, search); VCS
  colour tokens; a two-colour icon pass on the rail (Lucide, `list.icon` with
  `accent.base` when active, already close). Find bar stays a row (FB3, as
  JetBrains). Motion as the policy, nothing more.
- **Stays:** dock and rail, density, 12 px chrome, Material file icons, editor.
- **Cost:** 27 cards, P1–P27: the 24 shared plus P13 (one heading per tool
  window), P14 (the title bar) and P20 (the Git log tool window); all s or m.
- **Density risk:** low. Title bar +6 and breadcrumbs −2 net +4 px; everything
  else holds or tightens (CH2 gives back 52 px in the dock).
- **Fit:** the closest to "curated JetBrains-lite": the structure JetBrains
  users know, without its tool-window sprawl, and the Mac parts done properly.

### C. Quiet monochrome ("Zed / Linear / Sublime")

Chrome recedes until it's nearly invisible; the text is the interface.

- **References:** Zed, Linear, Sublime Text 4, iA Writer.
- **Changes:** monochrome Lucide everywhere, the coloured Material file icons
  off by default; colour only for state (errors, VCS, focus); borders replaced
  by background steps; title bar 38 with only the project name; the rail hidden
  until hovered; radius 6 throughout; the type ramp's body at 12 with lighter
  muted text; a floating find bar; minimal empty states (no icon).
- **Stays:** editor, density, dock structure.
- **Cost:** 29 cards: the 24 shared and P13, then C1–C4 (monochrome icons, the
  borderless pass, a floating find bar, rail auto-hide) in place of P14 and P20.
- **Density risk:** none; it's the densest.
- **Fit:** beautiful and calm, but not JetBrains-lite: it removes the
  information scent (coloured file types, visible tool windows) that makes
  JetBrains readable, and Zed already owns this look.

## Recommendation

**B, Curated New UI.** It's the only direction that matches the stated pillar
("curated JetBrains-lite, beautiful") without trading away density, which
editor-first can't afford. Its biggest wins are shared with every direction
(contrast floor, picker rows, toast, menus, one heading per tool window), so
the first cards are safe to ready whichever way the user leans. It borrows A's
native menus, sheets and dialogs, where native is plainly right on a Mac, and
leaves A's vibrancy and 13 px chrome as an Open question rather than a default.
C would make Tenmoku look like Zed; A would make it look like Xcode; B makes it
look like a lighter JetBrains IDE that belongs on macOS.
