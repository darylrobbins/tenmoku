# Audit the UI for polish and propose 2-3 visual directions: an audit capture mode for every surface, dark and light, and a per-surface findings doc with a card breakdown (no product visuals change)

## Problem

The user (2026-11-06) approved UI polish for the first public release: macOS-only, editor-first, with
"beautiful" (curated JetBrains-lite) as a stated product pillar. Polish here means spacing and type, motion,
empty states, the settings UI, theme quality, and how native menus, the title bar and dialogs feel.
**The user has not given a visual direction.** This card audits what is there and proposes directions.
It changes no product visuals. The user picks a direction before any implementation card is readied.

Mac-only: the captures render with Metal (TESTING.md, Screenshots).

## What exists, to build on (do not redo)

- `docs/design-language.md` (T1273) records **what the code does today**: colour tokens, the de-facto
  spacing scale (2, 4, 6, 8, 12, 16, 24), row and bar heights, radii, type sizes by role, icons, motion
  (none: no `with_animation` anywhere, no caret blink) and a Gaps list. This audit is the **should** next to
  that **is**. Cite its rules and gaps by section and do not repeat them. Do not edit it: T1396 has it in
  scope. Put proposed changes to it in the card breakdown.
- Screenshot harness: `kiln_platform::screenshots` (off-screen `VisualTestAppContext`, Metal, no screen
  permission needed). The existing scenes and goldens:
  - `crates/fe-workbench/examples/screenshots/`: `workbench` (dark), `setup_wizard_{dark,light}`,
    `file_icons_{dark,light}`, the token probe. `render <out.png> <dir>` shows a folder with nothing open.
    How a scene is written: `scenes.rs` (`write_project`, `use_settings`, `capture_with` and its `before`
    hook), `icons_scene.rs`, `setup_scene.rs`.
  - `crates/fe-gpui/examples/screenshots/`: editor scenes (selection, multi-cursor, minimap, sticky scroll,
    inline diagnostics, which-key popup, tabs, …).
  - `crates/fe-markdown-view/examples/screenshots/`: `markdown_preview_{dark,light}`.
  - `crates/fe-chat-view/examples/screenshots/`: `chat_*_{dark,light}`.
  - `kiln/crates/kiln/examples/gallery-screenshots/`: `gallery_{controls,lists,theme}_{dark,light}`.
- Repo convention for images: PNGs are committed **only** as goldens that a scene compares with.
  `docs/` holds no images. So this card commits **no PNG**. The audit's captures are regenerated by command
  into `target/ui-audit/`, and the doc names them by that path.
- Bundled themes: `crates/fe-config/themes/*.toml` (Tenmoku Dark, Light and Ember among them) over kiln's
  chrome bases in `kiln/crates/kiln-core/themes/`. T1418 (Monokai) is in flight. Audit it if it has landed
  by then, and otherwise say so.
- Start page: T1398 landed. T1425 (selection scroll and refreshing recents) is running, so this card waits
  for it.

## Deliverable 1: an `audit` capture mode (example code only)

Add `cargo run -p fe-workbench --example screenshots -- audit <out-dir>`. It renders every surface below,
**dark and light**, into `<out-dir>/<surface>_<dark|light>.png`, with **no golden comparison**. The default
compare run, which CI uses, stays exactly as it is.

- Put the new scenes in `crates/fe-workbench/examples/screenshots/audit_scenes.rs`. Further files must
  match `audit_*.rs`.
- In `main.rs` and `scenes.rs`, change only the `mod` declaration, the `Some("audit")` arm and the usage
  string.
- Reuse `write_project`, `use_settings` and `capture_with`.
- Surfaces:
  - workbench chrome (title bar on, tabs, rail, status bar, breadcrumbs)
  - project tree with git status
  - Start page (empty pane)
  - settings editor (a page with toggles, a select and a text field)
  - shortcuts editor
  - command palette open
  - a picker (file finder)
  - find bar with matches
  - search panel with results
  - an in-window prompt or dialog (kiln `prompt.rs`; folder trust or LSP consent)
  - a toast
  - terminal panel, if it renders off screen without a shell; otherwise skip it with a reason
  - git panel
  - git log with the commit card
  - problems panel
  - peek
  - hover and completion
- Render the chrome scene under **every bundled theme** (`<theme>.png`), for the theme-quality section.
- If a surface can't be opened through fe-workbench's public API from the example, **don't change `src/`**.
  Leave it out and record it in the doc as "needs a test hook" with the API it would need.
- Also run the other crates' existing examples (fe-gpui, fe-markdown-view, fe-chat-view, kiln gallery) and
  reference their `target/screenshots/` output or goldens. Don't add scenes there.
- Native chrome can't be captured off screen: AppKit's traffic lights, the macOS menu bar and its menus,
  NSOpenPanel/NSSavePanel/NSAlert sheets, and the Dock icon. Agents here have no screen-recording
  permission. List these under **Human captures** as exact steps for the user (what to open, which
  `screencapture -w` shot, file name) and audit them from the source:
  - `crates/fe-workbench/src/title_bar.rs` and `kiln/crates/kiln-platform/src/window_options.rs` for the
    title bar
  - the app menu definitions (`rg -n 'Menu' crates/fastedit/src kiln/crates/kiln-shell/src`) for menus
  - native versus in-window dialogs, by where `prompt_for_paths` and `kiln_ui::prompt` are used

## Deliverable 2: `docs/decisions/<lane>-ui-polish-audit.md`

Name it with the `<lane>-` prefix the other files in `docs/decisions/` use. Sections:

1. **Status**: `proposed`. The user approves. No implementation card is filed by this card.
2. **Captures**: a table with one row per PNG (path under `target/ui-audit/`, surface, theme), the exact
   command that regenerates it, and the Human captures list.
3. **Surfaces**: one subsection per surface above, plus native menus, title bar and dialogs, and themes.
   Each finding is a row with these columns:
   - category: alignment, spacing scale, type scale, contrast, radii/borders, focus ring, hover/pressed,
     empty state, motion, density, iconography, or native feel
   - what's wrong, concretely (values, not adjectives)
   - screenshot path
   - source `path:symbol`
   - proposed fix
   - effort (xs/s/m)
4. **Cross-cutting**:
   - a proposed spacing scale and type ramp (named roles to replace the literals, from design-language.md's
     Spacing and Type gaps)
   - radius and border rules
   - focus-ring and hover/pressed state rules
   - a motion policy: which transitions get motion, with durations and easing, and that Reduce Motion turns
     them off. GPUI has `App::reduce_motion`, but nothing sets it from the system yet. The accessibility design
     card filed beside this one (VoiceOver feasibility) covers that.
   - empty-state rules
   - WCAG contrast ratios of `text.primary`, `text.muted` and `text.disabled` on `surface.background`,
     `surface.panel` and `surface.raised`, for each bundled theme. Compute them with a throwaway script and
     don't commit it.
5. **Visual directions**: 2–3 named directions, each anchored on reference apps (for example "Xcode/Nova:
   native macOS, vibrancy, SF type ramp", "JetBrains New UI: dense, flat, strong icon set", "Zed: minimal,
   monochrome chrome"). For each: what changes in Tenmoku (tokens, spacing, type, radii, title bar, menus,
   motion), what stays, rough cost in cards, risk to the editor-first density, and fit with "curated
   JetBrains-lite, beautiful".
6. **Recommendation**: one direction, and why.
7. **Proposed card breakdown**: ordered cards, each `s` or `m`. Each one gives:
   - its scope globs (exact files; no `crates/*/src/lib.rs`)
   - dependencies
   - which findings it fixes
   - whether it regenerates goldens
   - Mac-only or Linux-OK

   Include the design-language.md update and the token-probe coverage of new scenes as their own cards
   where needed. Note which cards conflict with in-flight work (themes T1418, which-key icons T1396).
8. **Open questions for the user**: only the ones the direction choice needs.
