## Implementation notes

- Regenerate with `cargo run -p fastedit --example gen_user_docs`; `-- --check` writes nothing and exits 1
  with a summary of the lines that differ. `fastedit::user_docs_fresh reference_pages_are_up_to_date` runs
  the check, so every card that changes a setting (key, doc comment, type or default), a default binding,
  or a command or its title must regenerate `docs/user/src/reference/**` and have it in scope.
- The command catalog only checks IDs and can't list them. After review round 1 (F1), the scope was
  respecced to add `crates/fe-workbench/src/lib.rs` and `crates/fe-gpui/src/commands.rs`. Those files now
  build the catalog from parts that also list their commands (`fe_workbench::RECORDED_COMMAND_CRATES`,
  `fe_workbench::registry_commands()`, `fe_gpui::commands::catalog_commands()`). So the page lists exactly
  what the catalog knows, bound or not, and no GPUI app is started.
- Respecced the scope to add CONTRIBUTING.md: its "Tests and checks" section now names the regeneration
  command (C4).
