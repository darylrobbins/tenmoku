# Keep a file's undo history across closing and reopening it (editor.persistent_undo), like nvim's undofile

## Problem
Undo history lives in the `Buffer` (`crates/fe-buffer/src/buffer.rs`, `history: Vec<HistoryEntry>`) and dies with it. Close a file or quit and `u` has nothing on the next open. nvim with `undofile` (LazyVim sets it) keeps it, and VS Code's Local History is not undo. Hot exit (T526, `hot_exit.rs`) restores unsaved buffers with their dirty text but not their undo steps, and it does not need this card to work: its `Buffer::from_backup` restores text only. Hot exit itself already exists (`quitting doesn't ask about unsaved changes`, per the module docs), so no hot-exit card is needed.

## Change
- fe-buffer: new `crates/fe-buffer/src/undo_store.rs` and a pair of `Buffer` methods in buffer.rs: `export_undo(&self) -> Option<UndoRecord>` and `import_undo(&mut self, record: UndoRecord) -> Result<(), UndoImportError>`. `UndoRecord` is a plain serialisable value: the 64-bit content hash and byte length of the text the history ends at (the buffer's current text), and the user-origin entries in order, each with its batches' edits (offset range, old text, new text) and whether it is undone. Only a history made entirely of `Origin::User` entries is stored; one holding other origins (AI, LSP formatting) stores the longest user-only suffix that applies cleanly on top of the saved text, and none if that is empty. Entries are capped (1,000 entries, 4 MiB of text in all; the oldest drop first).
- `import_undo` applies only if the buffer's text hashes to the record's: it rebuilds the entries so `u` and `<C-r>` walk them with the carets of fe-vim's own record absent (fe-vim restores carets from its own table, `history.rs`; after an import `u` puts the caret at the start of the changed text, documented). A hash mismatch (the file changed outside) returns `Err(Stale)` and leaves the buffer untouched.
- `UndoStore { dir }`: `<state_dir>/undo/<fnv64(path)>.undo`, mode 0600 in a 0700 directory, written atomically by renaming a temporary file, as `local_history.rs` writes (same key scheme and permissions; read its module docs and match), format a small versioned binary or JSON-lines header plus entries, with a magic and version so an unknown version is ignored, a corrupt file is ignored and removed. Pruned like local history: files older than 30 days and beyond 500 files go (`prune`, called once per launch off the main thread).
- Wiring, in `crates/fe-gpui/src/pane_item.rs` beside the local-history global (`set_local_history`): a `set_undo_store` global installed in `crates/fastedit/src/main.rs` next to it; on opening a file-backed buffer, off the main thread read the record, and on the main thread `import_undo` when the buffer is still unedited and its text hash matches; after a save (the `record_history` call site in `finish_save`) and when the last editor of a clean buffer closes, write `export_undo()` on the background executor. A buffer restored from a hot-exit backup is not imported (its text is not the file's).
- Setting `editor.persistent_undo` (bool, default true) in `crates/fe-config/src/settings.rs`, `settings.schema.json` and `settings-template.toml`; false stops reading and writing and removes nothing.
- A file edited outside after the record was written has a different hash, so its stale history is simply not used (and is replaced at the next save).

## Known limits (lead decision after review round 3, 2026-11-07; these are NOT part of this card)
Under the review-round process, round 3's two medium findings, and round 4's F7 and F8, are left to follow-up cards that depend on this one. The reviewer should not hold this card to them:
- **Queued background writes after the setting turns off (round 3 F4; round 2 F4).** A background writer queued for a capture taken while its window kept history may still write or remove that file's record after the window turns `editor.persistent_undo` off, or after it starts waiting for its root's settings (a re-root). Only quitting drops such captures (`write_all_on_quit` → `forget_unless`, pinned by `undo_persist_tests::quitting_drops_waiting_writes_of_a_window_since_turned_off`). Dropping them when the policy changes, and a policy check in the writer, are follow-up T507.
- **Vim insert mode entered before the undo read lands (round 3 F5).** Entering insert mode opens a buffer transaction, and it opens one even before anything is typed. A read that lands while that empty transaction is open is refused by `Buffer::import_undo` (`Edited`). That open is not imported, and nothing retries after Escape. The buffer starts with no history. Its text, and the record on disk, are left as they were, so a later open with no edit in between still imports it (pinned by `undo_persist_tests::a_read_landing_in_an_open_empty_transaction_keeps_the_record`). Deferring or installing beneath the empty transaction is follow-up T508.
- **A read in flight when the window re-roots (round 4 F7).** A re-root makes the window wait for its new root's settings (`wait_for_window_persistent_undo`). Only reads started during that wait are deferred and restarted when the settings come in. A read already in flight that lands during the wait is dropped: `import_undo_into` finds `undo_store_for` is `None` for a waiting window and returns, and nothing defers it. Even with `editor.persistent_undo` on at the new root, that buffer starts with no history for this open. Its text and the record on disk are left as they were, so a later open with no edit in between still imports it. Deferring or restarting such a read, with the freshness checks kept, is follow-up T509.
- **Vim marks and folds set before a delayed import (round 4 F8).** `Buffer::import_undo` rebuilds the history with real edits. For a history that inserted rows, it deletes them for a moment and then puts them back. `import_undo_into` keeps every editor's selections through that, but nothing else: a Vim mark set on those rows before the import landed (by a delayed read, or a window waiting for its settings) has its row marked dead, so `'a` fails with E20 afterwards, and a fold closed over them is dropped by the display's catch-up. The text ends as it was, and the history is imported. Keeping marks and folds by position across the import is follow-up T510.
- **A live per-root change to the setting (round 5 F9).** A window's policy is set in `give()` (crates/fastedit/src/main.rs), which live reloads reach only through the `GlobalSettings` observer. Editing a non-launch root's project settings, or a user-settings change masked by the launch root's override, does not reach it: the window keeps its policy until it re-roots or the app restarts. Applying changes from every settings source the window uses, through workbench_root.rs `reload_settings`, is follow-up T512.

Round 4 F6 (an import into a buffer with a small history limit trimmed entries mid-rebuild and silently changed the text) is fixed here too: import must not trim while it rebuilds the history or restores the undo position, and enforces the limit afterwards without changing the text (C1).

The stale-settings race (round 3 F1, high) is fixed here, not left as a limit. Each window's settings loads carry the window's generation and root (bumped by every re-root and reload). A completion that is no longer the window's newest is discarded. It does not change the window's `persistent_undo`, release its deferred reads or reload its settings (C5).

## Implementation notes
- Scope widened to `crates/fe-buffer/src/lib.rs` (declares `undo_store`), `crates/fe-workbench/src/lib.rs` (declares `undo_persist_tests` at the crate root, so the ids are `undo_persist_tests::…`) and `crates/fe-editor/src/{lib,cursor_history,column_select}.rs`: `EditorModel::selection_state`/`restore_selection_state` put selections back after the import's edits with their primary, goals, the box selection under way (rebased to the new version, so it goes on) and the cursor history's earlier sets (re-anchored at their offsets), recording no navigation; `EditorModel::put_carets_at_change_start` has the imported transactions' undo and redo put one caret at the start of the first edit of the batch they end with, the spec's fallback, since no editor recorded their carets.
- The setting is per window, as settings are per root (an editor's window is the one it opened in, the one `restore()` gives it with `set_editor_window`, or the one GPUI last drew it in; a window's setting outlives the window, for its editors' close writes; an editor whose window isn't known keeps history only if no window has it off): main.rs's `give`/`watch_window`, which hand each window its root's settings (and drive `reload_settings`), call `fe_gpui::pane_item::set_window_persistent_undo`; a window given none falls back to the host's editor settings (`set_restore_style`). So it goes live without touching workbench_root.rs. The launch prune runs only with the setting on (off removes nothing).
- Wiring is a `cx.observe_new::<EditorView>` registered by `set_undo_store`: it tracks every editor (untitled too) with its buffer and window, reads the record for a file buffer's first editor, and imports it through whichever editor of the buffer is still open when the read lands, restoring every editor's selections (model `set_selections`, after catching up; no navigation). On release of a buffer's last editor, a clean buffer that has had history writes it. Saves and Save As capture `export_undo()` as the job is prepared and write after the save records: the live history if the buffer is clean, else the capture if it ends at the text saved. No history left to keep removes the record, unless the buffer never had any history (so a quick open/close or save can't delete a record still being read).
- Settings loads are numbered per window (`WindowSettings.loads`, bumped by each `settle`: every re-root and reload). `settle` starts one with `begin_load` (number and root); an off-thread read is applied through `finish_load` only if it's still the window's newest and the window still has that root, else dropped before it touches `persistent_undo`, the deferred reads or the settings.
- A window waits for its own root's settings before any persistence: main.rs's `watch_window` (and a re-root) calls `wait_for_window_persistent_undo`, and `give` resolves it, at once for the launch root's, else once read off the main thread; reads asked for meanwhile are deferred and run once the setting is in. Pending writes carry the window they were captured for, and quitting drops those whose window no longer keeps history.
- Writes: each file's newest capture waits in a shared map; a background writer writes whatever is newest when it runs (an older capture never lands last), and a failed write stays waiting. A read for a file opening takes a waiting capture over the disk. Quitting (`on_app_quit`) captures every clean open buffer and writes everything waiting synchronously, since gpui gives quit futures only 200 ms and doesn't run foreground tasks meanwhile.
- `export_undo` simulates the reverts and redos on a scratch snapshot with fe-buffer's own `revert`, so each entry's edits are as undo would apply them now (one forward batch per inverse batch). The undone tail is costed first, then applied entries newest first: the oldest drop. Each edit is charged its texts plus 24 bytes of offsets toward the 4 MiB, which bounds the file size. Entries changing no text (line-ending changes, empty restores) are skipped, not a stop.
- `import_undo` validates the whole record in string space first (hash and length, then every batch's old/new text at its range, char boundaries, no `\r`), then rebuilds by real edits: one edit back to where the history starts, each entry reapplied in a transaction (times restored), the undone tail undone. Subscribers see these edits; the text ends as it began and the buffer clean.
- `import_undo` lifts the buffer's history limit while it rebuilds the history and undoes the undone entries, then sets it back, so trimming drops only whole oldest entries once the history is complete and never leaves an entry's text behind (round 4 F6).
- Records are `<state_dir>/undo/<fnv64(path)>.undo`: magic, version, path (a key collision reads as none), hash, length, entries, and a trailing checksum. Unknown version: ignored and kept; corrupt: ignored and removed. `<dir>/.lock` is held across processes by every rename into the store and every removal (corrupt cleanup rechecks the bytes under it, `remove` checks the owner, prune holds it throughout), so a removal never takes a record renamed in after it looked. Temporary files are written unlocked, each writer its own; prune drops ones over an hour old.
